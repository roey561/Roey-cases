项目概览

S背景

在 MCN 跨境达人带货生态中，TikTok 小店的素材测品与达人筛选全程依赖人工。团队同时运营达人建联与短视频内容两大业务线，服务 MCN 旗下腰尾部达人及品牌自营账号，复盘效率成为规模化瓶颈。

T挑战

单条素材人工复盘耗时长达 30 分钟；腰尾部达人因缺乏专业策略指导，转化率极低，大量测品素材成本沉没。团队亟需一套可复用、可扩展的 AI 分析基础设施。

基于 Coze 平台，独立设计并搭建 CreatorOps AI——一套由 Agent 前台意图路由 + 双工作流后台构成的达人商业化复盘系统，覆盖达人建档与素材诊断全链路，支持自营账号与 MCN 达人双向接入。

LLM_C · 三镜头交叉归因诊断框架

L1
产品—受众
契合度分析
将产品 SKU 特征与历史档案受众画像（年龄、性别比、兴趣标签、地区）交叉比对，输出 1-10 分契合度评分与「受众真实需求」判断，决定是否值得重拍同款产品。
示例：「受众 53.7% 为 45-54 岁男性，偏好汽车工具；产品为宗教银饰——类目、语言、文化框架三重错位，fit_score=2」
L2
行动级
转化归因
若有留存曲线数据，精确到秒定位流失节点对应的创作者行为；若无留存数据，以内容缺口（fatal_content_gaps）与漏斗零转化确认为主要信号，识别 CTA 缺失等关键失败原因。
示例：「第 0:19 秒创作者停止说话并转移视线，40% 观众在此流失，且后续 10 秒内无购物车引导动作」
L3
历史爆款
公式偏差
将本次素材的视觉风格、开篇方式、CTA 手法与历史档案爆款基因（module_04）对比，量化偏差分数（1-10）并列举 deviations_found 数组。
示例：「历史爆款公式为「产品最优特性+限时报价直陈」；本次开篇为礼盒拆箱无价格信息——100% 偏离成功公式」

工程挑战与原创解法

从生产事故中提炼的三个核心工程原则
#01 Token 熔断：多模态附件计数导致逻辑崩溃
背景

Gemini 2.0 Flash 在被要求精确计数图片数量时，会陷入反复确认循环，消耗数万 Token 并最终引发逻辑漂移——这是在实际运行中真实触发的生产事故，而非理论推演。

解法

布尔值附件校验协议：改用 has_image / has_video 两个布尔值判断附件存在性，彻底绕开精确计数。Agent 只需知道「有没有」，数量清点交给后台工作流节点处理。

「防止大模型做它不擅长的事」比「修复它做坏之后的结果」成本低 100 倍。识别 LLM 的能力边界并在架构层绕开，是 Agent 工程的核心竞争力。
#02 错误传染：下游节点对上游报错 JSON 继续「努力分析」
背景

早期版本中，当上游节点返回 {"status": "error"} 时，下游 LLM 节点会将错误信息当成业务数据继续处理，输出一份充满幻觉的「分析报告」，且表面上格式完整、看起来合理。

解法

致命错误熔断协议（Fatal Error Circuit Breaker）：每个节点的 System Prompt 都设置前置核验规则——检测到 status:error 立即瘫痪，错误信息原样透传（透传链），禁止任何「待补充」或「N/A」占位编造。

「错误状态的传染性」是多节点 LLM 工作流中最危险的隐性风险。必须在每个节点的入口处单独防御，而不是在最终输出端统一拦截——因为那时幻觉数据已经无法溯源。
#03 角色越权：前台 Agent 自行扮演后端 API 输出伪 JSON
背景

Agent 在拦截用户请求时，会自发输出 {"status": "error", "code": 403} 等格式的 JSON 代码块——混淆前台拦截信息与后台工作流返回数据，导致前台排版逻辑误触发，产生跨场景逻辑漂移。

解法

身份锁定 + 终极输出禁令：用「大堂经理」角色约束 Agent 职责边界，系统级禁止前台输出任何 JSON 结构；同时设置 Zero-Text Invocation——工作流触发前禁止输出任何过渡文本，防止用户感知中间状态，也防止前台文本干扰后续渲染逻辑。

清晰的角色边界不只是工程规范，更是防止 LLM 产生「跨场景逻辑漂移」的核心约束机制。越权的根源不是模型能力问题，而是 Prompt 设计时角色边界模糊。

AI 工程方法论总结

从 CreatorOps AI 提炼的 5 条可迁移系统设计原则

以下原则提炼自完整的搭建历程——包括设计决策、生产事故与迭代修复——适用于所有基于 LLM 工作流的 AI 业务系统设计。

P1

防御性输入设计

在输入层就阻止大模型做它不擅长的事。布尔值替代精确计数，意图分层替代模糊语义理解，附件类型隔离替代混传。问题越早被拦截，修复成本越低。

减少 Token 消耗
防止逻辑漂移
P2

错误熔断透传原则

多节点工作流中，错误状态必须在每个节点入口处独立检测，检测到后立即停止并原样透传。绝不允许下游节点对错误数据进行「积极分析」，这是幻觉数据在链路中扩散的根源。

防止幻觉数据
在链路中扩散
P3

角色边界锁定

Agent 前台的职责只有一个：路由。分析、判断、生成全部交给后台工作流节点。清晰的角色边界是防止跨场景逻辑漂移的核心约束机制，也是系统排障时的关键依据。

提升系统可预测性
便于问题溯源
P4

多模型异构编排

不同节点根据任务性质选择最合适的模型：Gemini 2.0 Flash 处理多模态解析，GPT-4o 负责复杂推理与结构化输出，GPT-4o mini 处理格式转换——在质量与成本之间实现工程级权衡，而不是一律用最贵的模型。

降本增效
质量与成本平衡
P5

业务规则代码化

将运营规则、合规约束、输出格式要求全部写入 System Prompt 的「绝对红线」，而不是依赖大模型的泛化理解。规则越明确，系统越稳定，幻觉风险越低，维护成本越可控。

提升可维护性
降低幻觉风险
